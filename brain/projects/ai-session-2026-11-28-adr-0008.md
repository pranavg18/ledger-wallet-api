# AI session: drafting ADR-0008

**Tool / model:** Claude Code (Claude Opus 5.5)
**Driver:** Pranav Goyal
**Goal:** Draft ADR-0008 with `brain-query`: the append-only triggers, the database role boundary
and the FR-4.6 hash chain format.
[Issue #33](https://github.com/pranavg18/ledger-wallet-api/issues/33)

## What was done

- Read FR-4.1, FR-4.6, FR-5.5, NFR-DB-1 and NFR-PORT-1, and the three ADRs it has to fit: ADR-0005
  (#45), ADR-0006 (#65) and ADR-0007 (#43).
- Drafted `docs/adr/0008-ledger-immutability-and-hash-chain.md` from
  [[flyway-migrations-append-only-triggers]] and [[tamper-evident-logs-hash-chains]], and linked it
  from the ADR index and the traceability matrix.

## What worked

- Reading the other three ADRs first. ADR-0005's switch from `last_seq` to `max(seq) + 1` changed
  the tail-deletion analysis, and ADR-0006's lock statement fixed where `EntryHasher` is called.
- Writing the verification rule against the stored previous `hmac`, so one tampered entry gives
  one discrepancy, and then checking each tampering case in a table.

## What failed / needed correction

- The first draft invented two discrepancy types, with hashes as expected and actual values. They
  didn't match `docs/openapi.yaml`, which already has `HASH_CHAIN_BROKEN` and integer money
  fields. That was found while reviewing #66 and fixed to use the contract's type.
- The first draft counted the fixed key-check string as 37 bytes. It is 35, which a one-line
  check caught.
- Found by reasoning, not in the brain: a Java `Instant` holds nanoseconds and `timestamptz` only
  microseconds, so the timestamp has to be truncated before it is stored and hashed. The ADR makes
  this a rule for T3.1 and a test for T3.4.
